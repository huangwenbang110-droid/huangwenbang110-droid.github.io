演进线

每一代都不是平滑升级，中间有代价和取舍。文章里写的正是这些。

PHASE 01
Octopus · 第一代监控平台
自研采集 SDK 与平台应用层，覆盖日志与指标。底层用开源组件，上层自研。当时没有调用链——不是放弃，是没进视野。
PHASE 02
APM · 应用性能监控
业务方开始问"这个请求慢在哪一步"，日志和指标答不上来。第一次认真做技术评估，引入调用链。
PHASE 03
云原生应用可观测
指标、日志、调用链三信号统一，容器化与 Kubernetes 环境适配，平台规模上量。
PHASE 04
OpenTelemetry 统一
协议与语义迁移，存量兼容。迁移的代价是这一代最值得记录的部分。
PHASE 05
AIOps 与 AI 可观测
大模型做告警根因分析，只读 MCP 工具边界设计；AI 应用的 Token 成本治理与内容脱敏。
